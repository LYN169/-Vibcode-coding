# Regional Potential Lab 真实数据接入设计

## 目标与边界

从配置文件指定的只读原始目录读取七个真实数据文件，生成标准化中间文件、诊断报告和网页可直接加载的数据。原始文件不删除、不覆盖、不回写；所有派生结果仅写入项目 `outputs/processed/` 和 `outputs/diagnostics/`。

## 配置与加载

新增 `config/data_sources.json`，保存 `raw_data_dir` 和相对项目目录的 `processed_app_data_dir`。核心模块不硬编码外部磁盘路径。命令行预处理器读取配置并生成 `outputs/processed/app_data/` 下与现有加载器兼容的标准文件；网页优先读取上传文件和项目 `data/`，其次读取已生成的真实标准文件，最后才回退 sample。

## 实际字段映射

- 边界 `中国_县.geojson`：保留满足 `gb=156+6位代码` 的 2891 个 MultiPolygon，提取末6位为 `county_code`，`county=name`。7条空 `gb` 的“境界线”不是县域面，记录到报告后排除。CRS 从 EPSG:4490 转为 EPSG:4326。
- 经济 `economy_2019-2024.csv`：GBK 读取；`gdp_2019`、`gdp_2024` 转长表。`gdp_per_capita`、`gdp_density` 保持 NA，`economy_unit=亿元`。
- 夜间灯光：GBK 读取；仅保留7个已识别核心字段，过滤14条 `county_code` 非行政代码的坐标误拼记录；9位代码取末6位。
- 人口：UTF-8-SIG 读取；9位代码取末6位。2019 文件逻辑年份为2019；2024文件原始 `year` 错写2019，标准化时按文件名改为2024并记录自动修复。
- 路网：UTF-8-SIG 读取；静态截面复制为2019和2024，`road_data_note=静态路网截面数据，2019与2024共用`。面积和省份名称来自该表。

## 行政区名称处理

`province_code` 与 `city_code` 分别由县码前2位和前4位生成，并与路网字段交叉校验；`province` 使用路网来源。真实路网的 `city` 列全部为4位代码，不是地市名称。在没有权威名称映射表的前提下不猜测名称，标准化 `city` 暂保留该4位代码，并在两份报告中列为需要人工确认的问题。

## 主表和指标

以有效县域边界为主表，对2019和2024分别左连接经济、灯光、人口和静态路网。所有数值使用 `errors=coerce` 转换，非法值和原始空值保持 NA。合并后的两期长表先执行现有联合 min-max 标准化和 NA 动态权重，再按年份计算错配类型，最后计算跨期变化。GDP缺失不删除县域、不填0；经济统计三项缺失时仍可由灯光参与经济分项，综合潜力继续使用可用分项。

## 诊断输出

报告覆盖原始/标准行列、编码、字段、代码长度、重复、边界匹配、缺失比例、合并、得分可用性、几何和结论。四个CSV分别记录边界缺匹配、指标多余代码、字段缺失统计和重复代码。结论规则：无法生成双期主表或核心地图为“未通过”；存在可运行但需人工确认/自动修复的问题为“部分通过”；无实质问题为“通过”。

## 网页与测试

网页默认加载标准化真实数据，并显示静态路网说明。AppTest和Playwright覆盖三种年份模式、地图、真实表格、下载序列化和空间分析降级。由于全国2891县的999次LISA置换可能耗时，功能测试允许使用较小置换次数验证算法；网页保留原默认参数，但任何失败均降级而不阻塞其他功能。

## 已批准方案

用户已明确要求开始执行并给出完整映射、输出和测试规范，因此本设计按已批准方案实施。未采用把标准文件复制进原始目录或直接修改原始字段的方案，也未采用在线行政区名称猜测方案。
