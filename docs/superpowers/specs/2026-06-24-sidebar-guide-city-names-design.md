# Regional Potential Lab：侧栏说明与地市名称改造设计

## 1. 目标

本次改造包含两个相互独立但同时交付的变化：

1. 将主页面中的“数据源与计算口径”“数据完整性提示”“县域潜力快速诊断”移出首屏，收纳到左侧控制栏底部的“ⓘ 网站说明”小按钮中；
2. 使用民政部 2023 年县以上行政区划代码表，将网页中所有四位地市代码替换为可读的中文行政区名称，同时保留原始代码供筛选、导出和追溯。

## 2. 已选方案与备选方案

### UI 方案

- **已选：侧栏底部 Popover 小按钮。** 主页面更聚焦地图，点击后显示说明与动态诊断；最符合“小按钮”的要求。
- 备选：侧栏 Expander。实现稳定，但长期占据侧栏垂直空间，不够轻巧。
- 备选：自定义右侧抽屉。视觉自由度高，但需要非标准前端脚本，维护成本和 Streamlit 兼容风险较高。

### 行政名称方案

- **已选：官方页面提取后保存本地参考快照。** 可复现、可审计，网页运行不依赖联网。
- 备选：每次启动在线抓取。名称可能更新，但会受网络和民政部页面可用性影响。
- 备选：只手写当前 348 个代码。轻量，但来源追溯和后续更新能力较弱。

## 3. 信息架构

主页面保留以下顺序：

1. Hero；
2. 空间潜力与错配地图；
3. Moran's I / LISA 状态；
4. 结构与变化图表；
5. 诊断结果表与下载。

左侧栏现有年份、上传、权重、地区和空间分析控件保持不变。在侧栏最底部增加小按钮：

`ⓘ 网站说明 / GUIDE`

按钮打开后依次展示：

1. **平台介绍**：平台目的、分析对象、2019/2024 双期口径；
2. **使用说明**：选择年份、地区、指标和地图图层，查看提示并下载结果；
3. **数据源与计算口径**：真实数据状态、联合尺度标准化、NA 动态权重、静态路网、经济年份；
4. **当前数据完整性**：当前筛选县域数、GDP 缺失、缺失比例、可计算数、数据不足数和 weak 数；
5. **当前快速诊断**：县域数、潜力中位数、潜力释放区比例、跨期经济变化；
6. **数据限制与引用**：缺失值不插补、地市名称参考来源、空间分析可用条件。

主页面不再重复显示上述三块大模块。

## 4. 行政区划名称数据

权威来源：民政部《2023 年中华人民共和国县以上行政区划代码》：

`https://www.mca.gov.cn/mzsj/xzqh/2023/202301xzqh.html`

官方页面包含 3209 条有效六位行政区划记录。项目当前路网包含 348 个四位地市前缀。

本地参考表建议保存为：

`reference/mca_city_codes_2023.csv`

字段：

- `city_code`：四位地市前缀；
- `city`：网页展示名称；
- `province_code`：两位省级前缀；
- `source_code`：对应的六位官方代码；
- `mapping_type`：`official_prefecture`、`municipality`、`province_direct`、`special_region`；
- `source_year`：2023；
- `source_url`：民政部页面。

## 5. 映射规则

1. 普通地级行政区：使用官方六位代码中以 `00` 结尾、但不以 `0000` 结尾的记录，取前四位映射名称；
2. 北京、天津、上海、重庆：县级代码没有统一普通地级父记录时，映射为对应直辖市名称；重庆的 `5001` 和 `5002` 均显示“重庆市”；
3. `4190`、`4290`、`4690`、`6590`：分别显示省/自治区直辖县级行政区划名称；
4. `7100`、`8101`、`8200`：分别映射为台湾省、香港特别行政区、澳门特别行政区；
5. `6297`、`6298`、`6299`：属于源数据中的甘肃特殊区域，使用明确的“甘肃省特殊区域”标签并标记为 `special_region`，不得伪装成普通地级市；
6. 任何未来未覆盖代码不得直接显示四位代码。界面使用“未识别地区”，同时保留 `city_code` 并产生数据警告。

## 6. 数据流与字段

数据标准化阶段读取参考表并完成映射：

- `city_code`：保留四位代码，不覆盖；
- `city`：写入中文展示名称；
- `city_mapping_type`：记录映射类型；
- `city_mapping_status`：`mapped` 或 `unmapped`。

边界、路网、双期主表、地图 tooltip、地区筛选、结果表、CSV 和 GeoJSON 均使用同一映射结果，避免不同模块名称不一致。

V2 输出将从原始数据重新生成到 `outputs/real_data_v2/`；不得覆盖外部原始数据。

## 7. 错误处理

- 参考表缺失：流水线明确报错；网页已有历史输出时显示警告，不静默回退为代码；
- 重复 `city_code`：流水线终止并列出重复代码；
- 未映射代码：输出诊断 CSV/报告并在网页提示；
- 官方来源不可在线访问：不影响网页运行，因为项目使用本地快照。

## 8. 测试与验收

1. 当前 348 个四位地市代码映射覆盖率为 100%；
2. `city` 列不得存在 `^\d{4}$` 值；
3. `city_code` 仍为四位字符串且可追溯；
4. 2019、2024、对比模式均能运行；
5. 省份、地市、县区筛选均显示中文名称；
6. 地图 tooltip、结果表、CSV 和 GeoJSON 显示中文地市名称；
7. “ⓘ 网站说明”按钮位于侧栏底部，默认关闭，打开后六个说明区均可见；
8. 主页面不再显示三块原有大模块，地图上移；
9. 全部既有测试通过，并补充行政映射与说明按钮测试；
10. 浏览器验收无控制台错误、无页面错误、无横向溢出。

## 9. 范围边界

- 本次不修改指标权重、缺失值处理、错配分类和空间分析算法；
- 不把 2023 行政名称误表述为 2019 或 2024 当年历史区划；页面将注明其仅用于当前展示名称标准化；
- 不覆盖原始 `data` 文件，不删除旧版输出。
